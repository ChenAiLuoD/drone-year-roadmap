| Topic | 观察到的平均频率 | 该数值实际代表什么 |

| `/camera/image_raw` | 2.109 Hz（由 bag 元数据计算） | 30 条消息 ÷ 14.2225 秒的录制跨度；不是回放订阅端的实测接收频率。 |
| `/perception/detections` | 2.158 Hz（最后监测窗口） | `ros2 topic hz` 在重试时观测到的接收频率；启动积压会影响该窗口，不能当作稳定 YOLO FPS。 |
| `/perception/tracks` | 2.158 Hz（最后监测窗口） | 与检测 Topic 同轮重试得到的接收频率；不是单次 IoU 匹配耗时。 |
| `/perception/annotated_image` | 未得到有效 `topic hz` 样本 | 可视化节点日志已证明完整回放发布 30 条；命令行监测器未留下可用的图像频率数据。 |

## 回放完整性与采样限制

- 第 3 天的完整回放中，检测、跟踪和标注图像各发布 30 条，与原始运行一致；回放前节点图只有检测、跟踪和可视化节点，没有视频源节点。
- 原始与回放的检测、跟踪 `source_time` 范围都为 0.000—0.484 秒，说明下游结果保留的是来源图像时间，而不是回放时的系统时间。
- 第 4 天第一次和重试的图像 Topic 监测器均未形成可用平均值；重试前已确认其订阅关系存在，因此本记录只陈述该现象，不将其解释为图像 Topic 没有发布。
- ROS Humble 当前的 `ros2 topic hz` 命令不提供 QoS 覆盖参数。对于本次高分辨率图像 Topic，不能仅依赖该命令的空日志得出吞吐或丢帧结论。

| 阶段 | 当前是否测量 | 说明 |

| rosbag 读取与图像发布 | 部分 | 通过 `/camera/image_raw` 的到达频率观察吞吐，但未测每条消息读取耗时。 |

| 框绘制 | 否 | 当前未在绘制函数前后记录计时。 |

| 端到端延迟 | 否 | 没有在每个阶段记录同一帧的进入与离开时刻，因此不报告端到端延迟。 |

## 结果解释

本次记录描述的是固定参数下的 Topic 吞吐，不构成完整实时性能结论。
后续若需要测量延迟，应在解码、检测、跟踪、绘制和写盘边界分别增加计时，
并说明是否包含 ROS 序列化、排队、日志输出和磁盘 I/O。
